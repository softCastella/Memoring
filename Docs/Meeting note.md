# Meeting note — Memoring 1차 구현

- 날짜: 2026-09-17 (저녁 작업은 09-18 00:30까지)
- 참석: 운영자, 모바일 앱 개발
- 목적: 감성 체크리스트 앱 1차 범위 구현 결과를 정리하고, 다음 작업을 남긴다.

## 결정

- 기존 저장소에는 README만 있었으므로 Android 우선 Flutter/Dart 프로젝트로 시작했다.
- 앱 표시 이름은 아직 확정되지 않았다. `lib/config/app_config.dart`의 `AppConfig.appName`만 바꾸면 된다. 네이티브 런처 이름은 AndroidManifest / Info.plist에도 맞춰야 한다.
- 최초 실행 기본 디자인은 사진 없는 로즈 테마(웜 아이보리 배경, 브라운 글자, 더스티 로즈 포인트)다. 사진 배경과 반투명 카드는 사용자가 선택했을 때만 적용한다.
- 1차에서는 외부 서버·유료 호스팅·실제 결제를 만들지 않는다.
- 사용자 개인 할 일·감정 메모를 운영자가 보는 기능은 만들지 않는다.
- 할 일과 매일 반복은 한 목록에 섞인다. `repeatsDaily`는 분류와 별개 플래그다.
- 주제별 체크리스트는 페이지로 나눈다. 기본 페이지는 받은함(`오늘`).
- 관리자는 앱 안이 아니라 별도 웹(로컬 `http://localhost:8081`)을 쓴다. 앱 미리보기는 `http://localhost:8084`로 고정한다.
- 유료 배경은 클라이언트 구매 플래그만으로 열지 않는다. 서버 검증 전에는 무료 팩만 허용한다.
- 상업용으로 쓸 수 있는 무료 명조(고운바탕, SIL OFL)를 본문에 쓴다.

## 이번에 구현한 것

### 앱 (오늘 / 기록 / 꾸미기 / 설정)

- 오늘: 날짜 선택, 월~일 주간 줄, 전체·공부·루틴·할 일 분류
- 항목 추가·수정·삭제·완료/완료 취소. 제목, 날짜, 분류, `매일 다시`(자정 지나도 같은 자리)
- 선택한 날짜의 완료 수 / 전체 수, 빈 화면 안내, 목록 아래 `+ 할 일 추가`
- 완료 항목은 제목만 취소선. 선은 마지막 글자에서 조금만 삐져나온다
- 앞머리 핸들을 잡아 위아래 순서 변경. 웹/데스크톱은 바로 드래그, 모바일은 길게 누름
- 주제 페이지: `오늘`, `매월 소비` 등. 페이지 줄에서 `+ 페이지` / `+ 항목` 타원 뱃지
- 선택 페이지는 진한 갈색 타원, 날짜는 숫자 아래 작은 점, 분류 탭은 밑줄
- 루틴 완료는 날짜별로 따로 저장된다. 어제 기록이 오늘에 덮이지 않는다
- 기록: 지침·차분·평온·설렘·기쁨, 짧은 메모, 저장, 지난 날짜 조회. 오늘 화면에 저장한 마음은 “지난 기록”이 아니라 기록 탭에서 본다
- 꾸미기: 로즈 / 세이지 / 오트 / 나이트. 갤러리 이미지 위치·확대·흐림·카드 투명도, 적용 전 미리보기, 배경 제거, 기본 디자인 복원
- 선택한 이미지는 앱 문서 폴더에 복사해 임시 경로에 의존하지 않는다
- 설정: 꾸미기, 배경 스토어, 내 배경, 기본 디자인 복원
- 할 일, 루틴 완료, 감정, 꾸미기, 페이지를 기기 로컬 JSON에 저장. 첫 실행 실제 데이터는 비어 있음. 미리보기는 `--dart-define=USE_SAMPLE_DATA=true`
- 웹 미리보기는 폭 430 안에 로즈 배경이 그려진다. 바깥 어두운 갈색이 화면을 덮지 않게 맞춰 두었다

### 배경 스토어 (앱)

- 설정·꾸미기에서 배경 스토어, 내 배경
- 공개된 팩 목록·카테고리·미리보기. 무료 팩은 다운로드·적용
- 유료 팩은 잠금. 서버 확인 없이 열리지 않는다
- **미완료:** 관리자(8081)에서 만든 공개 무료 팩이 앱(8084) 스토어에 아직 안 들어온다. 포트가 달라 브라우저 저장소가 갈린다. 숨은 브릿지(`web/catalog_bridge.html`)를 넣었으나 동작 확인에 실패했다. 아침 우선 작업

### 운영자 배경 관리 (로컬 웹)

- 실행: `flutter run -d chrome -t lib/admin_main.dart --web-port=8081`
- 배경팩 생성·수정, 이미지 등록·순서 변경·삭제
- 팩 이름, 소개, 카테고리, 무료/유료, 비공개/공개
- 유료는 금액 숫자가 아니라 스토어 상품 ID를 적는다. 관리자 화면의 숫자만으로 결제 금액이 바뀌지 않는다
- 관리자 비밀번호는 앱 소스에 넣지 않는다. 개발 모드에서 브라우저/기기에만 저장하거나 `--dart-define=ADMIN_PASSWORD=`로 전달한다
- 비공개 초안은 관리자에만 남는다. 공개로 저장해야 스토어 대상이다
- 앱 설정 안에 관리자 입구를 두지 않는다. 8081 관리자 화면을 그대로 쓴다

### 홈 화면 위젯 (Android 소스)

- 소형 진행률, 중형 오늘 할 일 일부와 체크. `home_widget` + 네이티브 레이아웃
- 앱이 `widget_snapshot`을 쓰고 위젯과 맞춘다
- **미완료:** 이 환경에서 에뮬레이터/실기기 라이선스가 막혀 홈 화면에 올려 보지는 못했다. 앱 안 미리보기만으로 완료로 보지 않는다

## 실행 방법

앱 (웹 미리보기 포트 고정):

```bash
flutter run -d web-server --web-hostname localhost --web-port=8084 --dart-define=USE_SAMPLE_DATA=true
```

관리자:

```bash
flutter run -d web-server --web-hostname localhost --web-port=8081 -t lib/admin_main.dart
```

이 환경에는 Android cmdline-tools/에뮬레이터가 없어 실기기 실행은 확인하지 못했다. Windows 데스크톱은 Developer Mode(심볼릭 링크) 때문에 막혔다.

## 검증 결과

- 단위·위젯 테스트: 항목 CRUD, 섞인 목록, 순서 변경, 주제 페이지, 무료 팩 적용, 유료 잠금, 위젯 스냅샷, 관리자 팩 생성은 통과했다
- 관리자 → 앱 스토어 실기기(브라우저) 연동은 실패. 아침 이어서 볼 것
- 갤러리 선택, 실제 키보드, 실기기 레이아웃은 에뮬레이터가 없어 실행 검증하지 못했다

## 아직 구현하지 않은 것

- 관리자 공개 팩이 앱 배경 스토어에 나타나는 것 (로컬 8081↔8084)
- 실제 기기에서 Android 홈 화면 위젯 확인
- 외부 서버, 운영용 관리자 웹 배포, 운영 인증
- 구독, 결제, 구매 복원

## 후속 작업

0. **(아침 우선)** 관리자 8081에서 공개한 무료 팩이 앱 8084 배경 스토어에 보이게 한다. iframe/localStorage 브릿지가 실패한 원인을 보고, 같은 주소에서 관리자를 열거나 로컬 전송 방식을 다시 정한다. 포트(8081/8084)는 바꾸지 않는다.
1. Android cmdline-tools / 에뮬레이터 또는 실기기를 준비한 뒤 앱 실행 검증. 특히 갤러리 배경, 키보드, 작은 화면, 홈 위젯.
2. 홈 화면 위젯 실기기 확인. 앱과 완료 상태 동기화.
3. 배경 스토어 운영 연결
   - 팩 목록은 서버에서 받기. 앱 재배포 없이 배경 추가
   - 구매 권한은 서버 검증. 클라이언트 구매 여부만으로 유료 콘텐츠를 열지 않는다
4. Play Console 상품 ID와 관리자의 `storeProductId` 연동. 관리자 화면에서 금액만 바꿔 결제가 바뀌게 만들지 않는다.

## 다음 단계에 필요한 외부 설정

- Android SDK cmdline-tools, 에뮬레이터 또는 실제 기기
- 홈 위젯용 Android 네이티브 확인
- 배경 파일 호스팅과 구매 검증 서버
- Play 인앱 상품, 스토어 결제 계정 (없으면 실제 결제로 보고하지 말 것)
- 관리자 웹 운영 배포 시 인증 제공자 (비밀번호를 앱 코드에 넣지 말 것)

# 2026-09-18 LOOP 사이트와 메모링 상세 공개

- 날짜: 2026-09-18
- 참석: 운영자, 모바일 앱 개발
- 목적: 메모링 소개용 LOOP 라인 홈·상세를 만들고 운영에 올린 결과를 남긴다.

## 결정

- LOOP 홈(`https://loop.tycheworks.com/`)은 메모링 브랜드·로고다. 앱 데모 화면은 홈에 두지 않고 상세에만 둔다.
- 상세 특징 순서는 첫째 자정에 다시 채워지는 체크리스트, 둘째 스킨 시스템이다.
- 상세 스크린샷은 원본 가로를 넘기지 않는다. 데모 크롭은 428px, 폰 화면은 약 425px.
- 사이트 원본은 Memoring 앱 저장소가 아니라 `chemical-safety-vr-server`의 `public/site/loop`다.
- 로컬 앱 포트는 그대로다. 관리자 8081, 미리보기 8084, 카탈로그 8090.

## 이번에 한 일

- LOOP 홈: Spark/Immersa와 같은 히어로·작품 카드·비전. 작품 제목은 텍스트 `메모링`.
- 메모링 상세: 소개 / 체크리스트 / 스킨 / 설정 / 정보. 스킨 적용, 내 스킨, 설정 실화면을 각 구간에 배치했다.
- 운영 공개: GitHub `main@da743d7`, 운영 브랜치 병합 `7a07f0e`. Nginx·PM2·DB는 건드리지 않았다.
- 확인한 주소: `https://loop.tycheworks.com/`, `https://loop.tycheworks.com/memoring/`.
- 앱 쪽: 밝은 사진 스킨이면 글자를 어둡게 맞추는 대비 로직을 넣었다. 소스 파일은 아직 이 저장소에 커밋하지 않았다.

## 검증

- 서버 저장소에서 LOOP·SEO·캐러셀 관련 테스트 22개 통과.
- 운영 HTML이 홈·상세 본문을 반환하는 것을 확인했다. 실기기 브라우저 레이아웃은 아직이다.

## 후속

- 메모링 앱 저장소의 미커밋(위젯, 카탈로그, 스플래시, 사진 대비 등)은 이 문서 커밋에 넣지 않았다. 별도 커밋이 필요하다.
